Overview

Aegis is a dependency-free, self-hosted authentication portal built with Node.js using only built-in modules. It provides a complete authentication solution with modern security practices, a polished responsive UI, and no external dependencies.

The system is designed with security-first principles, implementing defense-in-depth strategies to protect user credentials and sessions.

Architecture

Backend (server.js)

Node.js ESM server using only built-in modules (http, crypto, node:sqlite). Handles routing, authentication logic, session management, and security middleware.

Frontend (public/)

Responsive dark-themed UI with vanilla JavaScript. Includes tabbed login/register forms, real-time validation, and an authenticated dashboard.

Storage (SQLite)

Local SQLite database using Node's built-in sqlite module. Uses WAL mode, foreign keys, and proper indexing for performance and integrity.

Security Features

Password Security

Scrypt Hashing

Passwords are hashed using scrypt with parameters N=32768, r=8, p=1, generating 64-byte keys with 16-byte random salts.

Constant-Time Comparison

All cryptographic comparisons use crypto.timingSafeEqual() to prevent timing-based attacks.

User Enumeration Protection

Uses a pre-computed dummy password hash for non-existent users to ensure consistent timing regardless of account existence.

Session Management

Opaque Tokens

32-byte cryptographically secure random tokens are generated using crypto.randomBytes() and only SHA-256 hashes are stored in the database.

Secure Cookies

Cookies are marked HttpOnly, SameSite=Strict, and Secure (auto-detected based on connection). Sessions rotate on login, register, and logout.

Session TTL

Authenticated sessions expire after 24 hours, anonymous sessions after 1 hour. Expired sessions are automatically cleaned up.

Attack Prevention

Protection Description
CSRF Protection Per-session CSRF tokens validated via X-CSRF-Token header on all state-changing requests with constant-time comparison.
Origin Validation Checks Origin header against request host for state-changing requests. Rejects cross-origin requests.
Fetch Metadata Validates Sec-Fetch-Site header, allowing only same-origin or direct navigation requests.
Rate Limiting Sliding window rate limiting on logins (30/IP, 6/account per 15min), registrations (8/IP per hour), and session creation (60/IP per hour).
Request Hardening JSON-only for POST, 8KB body limit, method allowlists, input validation, and connection timeouts (15s request, 10s headers, 5s keep-alive).
Input Validation Usernames: 3-32 chars, alphanumeric and underscores only. Passwords: 12-1024 characters. Case-insensitive username uniqueness.

Security Headers

Header Value Purpose
Content-Security-Policy default-src 'none'; script-src 'self'; style-src 'self'; ... Prevents XSS by restricting resource loading
Strict-Transport-Security max-age=31536000; includeSubDomains Forces HTTPS (when secure connection detected)
Cross-Origin-Opener-Policy same-origin Isolates browsing context
Cross-Origin-Resource-Policy same-origin Prevents cross-origin resource embedding
Permissions-Policy camera=(), microphone=(), geolocation=(), payment=(), usb=() Disables sensitive browser features
Referrer-Policy no-referrer Prevents referrer leakage
X-Content-Type-Options nosniff Prevents MIME type sniffing
X-Frame-Options DENY Prevents clickjacking

API Endpoints

All endpoints are prefixed with /api/. State-changing endpoints require Content-Type: application/json and a valid X-CSRF-Token header.

GET /api/session
Returns current session information. If no session exists, creates an anonymous session with a new CSRF token.
Response: { authenticated: boolean, user: object|null, csrfToken: string, expiresAt: number }
POST /api/register
Creates a new user account and establishes an authenticated session.
Body: { username: string, password: string }
Validation: Username 3-32 chars (alphanumeric/underscore), password 12-1024 chars
Response: { authenticated: true, user: object, csrfToken: string, expiresAt: number } (201 on success)
Errors: 400 (invalid input), 409 (username taken), 429 (rate limited), 403 (CSRF/origin)
POST /api/login
Authenticates an existing user and rotates session.
Body: { username: string, password: string }
Response: { authenticated: true, user: object, csrfToken: string, expiresAt: number }
Errors: 401 (invalid credentials), 429 (rate limited), 403 (CSRF/origin)
POST /api/logout
Terminates current session and creates a new anonymous session.
Body: {}
Response: { authenticated: false, user: null, csrfToken: string, expiresAt: number }
Errors: 403 (CSRF/origin), 429 (rate limited)

Setup & Usage

Prerequisites

  • Node.js >= 24 (uses built-in node:sqlite)
  • No external npm dependencies required

Installation & Running

git clone https://github.com/mukitkhan699/aegis-login.git
cd aegis-login
cp .env.example .env
npm start

The server will start at http://127.0.0.1:3000 by default. npm start loads variables from .env automatically; running node server.js directly uses only exported environment variables.

First Use

  1. Navigate to http://127.0.0.1:3000 in your browser
  2. Click "Create account" to register a new user
  3. Enter a username (3-32 alphanumeric/underscore) and password (minimum 12 characters)
  4. You'll be automatically logged in and redirected to the dashboard
  5. Use "Sign out" to end your session

Configuration

Configure the application using environment variables:

Variable Default Description
PORT 3000 Server listening port
HOST 127.0.0.1 Server listening host (use 0.0.0.0 for external access)
DATABASE_PATH ./data/auth.db Path to SQLite database file
TRUST_PROXY undefined Set to 1 only behind a trusted reverse proxy. Use TRUST_PROXY_HOPS and PUBLIC_HOST. Headers are validated.
COOKIE_SECURE auto Set to true or false to override auto-detection of secure cookies

Example with Environment Variables

PORT=8080 HOST=0.0.0.0 TRUST_PROXY=1 TRUST_PROXY_HOPS=1 PUBLIC_HOST=example.com COOKIE_SECURE=true node server.js

Database Schema

The SQLite database is automatically created on first run in the data/ directory.

Users Table

Column Type Description
id INTEGER PRIMARY KEY AUTOINCREMENT Unique user identifier
username TEXT NOT NULL UNIQUE COLLATE NOCASE Username (case-insensitive uniqueness)
password_hash TEXT NOT NULL Scrypt password hash in format: scrypt$N$r$p$salt$hash
created_at INTEGER NOT NULL Unix timestamp (milliseconds) of account creation

Sessions Table

Column Type Description
token_hash TEXT PRIMARY KEY SHA-256 hash of the session token
user_id INTEGER REFERENCES users(id) ON DELETE CASCADE Associated user (NULL for anonymous sessions)
csrf_token TEXT NOT NULL CSRF token for this session
created_at INTEGER NOT NULL Unix timestamp of session creation
expires_at INTEGER NOT NULL Unix timestamp of session expiration

Database Features

  • WAL Mode: Write-Ahead Logging for better concurrent access
  • Foreign Keys: Enabled with CASCADE delete for sessions when users are deleted
  • Secure Delete: Overwrites deleted data to prevent recovery
  • Busy Timeout: 5 seconds to handle concurrent access
  • Auto Cleanup: Expired sessions are deleted every 5 minutes
  • File Permissions: Database file set to 600 on POSIX systems
